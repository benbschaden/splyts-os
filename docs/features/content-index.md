Feature: Universal content index

  Background:
    Given I am logged in as a member of an organization
    And the organization has content (outputs, documents, discussions, contacts, etc.)

  Scenario: Content is indexed when created
    Given I create a new output in a project
    When the output is saved
    Then a content index entry is created with content_type "output" and the output's ID
    And the entry has a title, summary, and embedding
    And the entry belongs to my organization

  Scenario: Content is re-indexed when updated
    Given an output exists with a content index entry
    When I edit the output's content
    And the output is saved
    Then the content index entry is updated with a new summary and embedding

  Scenario: Content is removed from index when deleted
    Given an output exists with a content index entry
    When the output is deleted
    Then the content index entry is also deleted

  Scenario: Short-form content uses direct text as summary
    Given I create a company milestone with title "Launch Beta" and description "Opened beta to first 50 users"
    When the milestone is saved
    Then the content index entry summary is derived from the title and description directly
    And no AI summarization call is made

  Scenario: Long-form content gets AI-generated summary
    Given I create a document with 2000 words of content
    When the document is saved
    Then the content index entry summary is generated by AI from the document content

  Scenario: Search finds content across all types
    Given outputs, documents, and contacts exist in the organization
    When I search for "onboarding feedback"
    Then the results may include outputs, documents, and contacts
    And each result includes the content_type, title, summary, and similarity score

  Scenario: Search respects organization isolation
    Given another organization has a document about "onboarding"
    When I search for "onboarding"
    Then only results from my organization are returned

  Scenario: Search can filter by content type
    Given outputs and documents exist
    When I search for "brand voice" with type filter ["document"]
    Then only documents are returned

  Scenario: AI context retrieval uses the content index
    Given content is indexed across multiple types
    When I use the AI chat and ask a question
    Then the retrieval pipeline searches the unified content index
    And relevant context from any content type is included in the AI prompt
